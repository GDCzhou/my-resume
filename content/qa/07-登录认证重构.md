# QA：登录认证服务 DDD 重构

> 来源项目：登录认证服务（绞杀者模式迁移）
> 简历对应：`opencode_write_resume.md` → "登录认证服务 DDD 重构（主导）"
> 技术栈：Java 21 · Spring Boot 3.4 · Spring Cloud Alibaba · Redis · JWT · ArchUnit

---

## Q1 ⭐ 重构前的问题是什么？为什么必须重构？

**答**：旧认证服务是一个 **560 行上帝类 `SysLoginService`**：
```
一个方法混入：校验、调远端、写 Redis、审计、签 token —— 五件事
9 种登录方式全堆在一个类里
缺少失败锁号等防暴力破解机制（P0 安全漏洞）
```

**重构目标**：分层 + 适配器 + 充血聚合根，零中断迁移。

## Q2 ⭐ 怎么建模登录？新增登录方式成本多少？

**答**：
```
上帝类 → 分层架构 + 9 个登录适配器
loginType 整数 → 枚举 + Dispatcher 路由
失败锁号规则 → 收进充血聚合根 LoginAttempt：
  失败 3 次验证码 / 5 次锁号 30 分钟（规则可单测）
```

**效果**：新增登录方式从"改几百行上帝类"变成"**加一个适配器**"。**开放-封闭原则**的落地案例。

## Q3 ⭐ 端口倒置（依赖倒置）怎么做的？

**答**：
```
业务层定义端口接口（port）—— 业务要"发短信、查用户、签 token"，不关心实现
Redis / Feign / 签 token 全部下沉适配层（adapter）
外部 DTO 与内部模型分离（防腐层 + Mapper 边界翻译）
```

**效果**：换 Redis 只换一个实现类；业务层可单测（mock 端口即可，不依赖真实 Redis/Feign）。

## Q4 ⭐ baseline 五元组对拍是什么？怎么证明行为等价？

**答**：重构的核心是"**零中断、行为等价**"——用五元组对拍机器验证：
```
五元组 = 入参 / 前置数据 / 调用 / 输出 / 字节级响应
43 用例覆盖 22 接口
新旧系统双跑 → diff 通过才算等价
```

**施工中抓出漏洞**：短信码校验整体缺失（**任意码放行**）——鉴权绕过级 P0 漏洞，重构过程中发现并修复。

**面试亮点**：重构的两种价值——"安全替换旧系统" + "暴露隐藏 bug"。能讲出抓出任意码放行，比任何架构名词都有说服力。

## Q5 ⭐ 绞杀者模式迁移怎么保证下游老服务兼容？

**答**：
```
v1 / v2 共存灰度切流
适配器复刻 v1 有状态会话格式（FastJSON2 @type 胖会话）—— 保证下游旧服务可读
标注为"绞杀债"待 v1 下线整包删除
```

**关键**：不是"新系统上线就切"，而是"新旧共存，新系统兼容旧格式，灰度切流，旧系统彻底下线才删兼容代码"。

## Q6 虚拟线程的坑怎么修的？（RequestContext 丢失）

**答**：虚拟线程切换会丢失 ThreadLocal —— 导致**客户端 IP 恒空**。修复：
```
自有 InheritableThreadLocal + Filter 捕获
```
**为什么用 InheritableThreadLocal**：虚拟线程池会复用线程，普通 ThreadLocal 在任务切换时丢；Inheritable 让子虚拟线程继承父线程的上下文。

## Q7 架构治理怎么防回退？

**答**：分层红线以 **ArchUnit 双档**（结构档 + 严格档）锁定并随单测强制执行：
```
结构档：基础分层方向（领域不依赖框架）
严格档：所有架构意图（禁 System.out、禁错误依赖方向）
```
**面试要点**：架构治理的关键是"**可执行、防回退**"——不是写文档，是写测试，违反就构建失败。
