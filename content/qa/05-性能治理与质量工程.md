## Q1 ⭐ 32 处慢 SQL 怎么治理的？列举几类手段

**答**（智慧健康云平台）：

```
① LIMIT 1 短路：查询只要一条却全表扫 → 加 LIMIT 1 减少扫描量
② 字段裁剪：SELECT * → 只查需要的列
③ 校验下沉 SQL：Java 循环校验 → SQL 条件（如 stock > 0、状态前置）
④ N+1 → 批量：循环单查 → 批量 UPDATE（一次 SQL 更新多条）
```

**面试要点**：慢 SQL 治理的核心是"先定位（慢查询日志/EXPLAIN）再治理"——别只说手段，要说排查路径。

## Q2 为什么敢大规模改 SQL？怎么保证行为等价？

**答**：建了**特征测试快照基线（5518 行）**——改造前先跑出结果快照，改造后再跑对比，diff 通过才算等价。**特征测试**把"行为等价"从"人工保证"变成"机器验证"，这是大规模重构的前提。

**面试加分**：提到"先锁行为再改造"——面试官会认可你的工程严谨性。

## Q3 MQ 消费堆积怎么定位的？OOM 事故怎么处理的？

**答**：
```
消费堆积：线程池参数 Nacos 动态化（发现堆积改配置不重启）+ 定位根因空指针修复
OOM 事故：heap dump → 定位到大单整单装载（一次加载全量数据到内存）
  → 改为分批 + 缓存（不一次全量 load）
```

**面试要点**：OOM 是必考题——**heap dump 分析是标准答案**，别只说"内存不够"。

## Q4 ⭐ DDD 六边形架构是什么？你们怎么落地的？

**答**（导检系统 + 登录认证重构）：

```
领域层（domain）：纯业务逻辑，零框架依赖（0 个 Spring import）
端口层（ports）： 纯接口/record，定义"业务要什么"
适配层（adapter）：把 Redis/MQTT/HTTP/持久化实现成端口
依赖方向永远朝内：领域 → 端口 ← 适配器（业务不依赖技术）
```

**核心价值**：技术选型可替换（换 Redis 只换一个实现类）、业务可单测（不依赖框架）、架构约束可固化（ArchUnit）。

## Q5 ArchUnit 怎么把架构意图变成构建期红线？

**答**：21 条 @ArchTest 规则（其中 11 条分层红线），随全量单测执行，**违反即构建失败**：

```
禁止依赖：领域层不得 import java.util.concurrent / 响应壳 / HTTP
禁止卫生：System.out / printStackTrace
外部边界：Feign / 老 common / LoginUser 只能适配层碰
```

**面试要点**："架构规则要能执行，不能只写在文档里"——ArchUnit 就是把文档规则变成测试。

## Q6 ⭐ 单线程事件循环是什么？为什么用它不用分布式锁？

**答**（导检系统）：所有共享状态变更投递到**单线程事件循环**串行执行，从根上消除竞态：

```
优势：天然原子（一个线程处理，无并发冲突）、正确性优先
代价：主动放弃并行度
权衡：避免一开始就背锁复杂度；演进路线是压测出瓶颈后按节点分片，
     而不是预置分布式锁
```

**面试要点**：能说清"为什么选单线程"（正确性优先 + 避免锁复杂度）比"用了单线程"更有价值——这是技术决策的权衡思维。

## Q7 ⭐ 调度引擎怎么建模的？怎么验证算法正确？

**答**（导检系统）：
```
建模：体检套餐 = 带前置依赖的任务 DAG（prereqs 硬约束 + priority 软偏好）
决策：用"预计完工时间"（步行+预计等待+服务时长）替代"按队伍长度"选房间
    数字孪生用 EWMA 估计设备服务时长
验证：策略对照仿真（300人/组 × 10组随机种子）
     平均等待 -4.6%、在院时长 -4.4%，9/10 组占优
    算法核心 61 项用例 + 与 Python 仿真逐位对拍（轨迹黄金 JSON 152 决策全等）
```

**面试要点**：算法题要能说"怎么验证的"——对拍 + 随机种子仿真是最有说服力的验证方式。

## Q8 RAG 系统怎么保证检索质量？

**答**（报告解读系统）：
```
两段式检索：宽召回（top-20）+ cross-encoder 精排
评测：黄金集 A/B 实测 context precision 0.323 → 0.369（+14%）
坑：定位重排副作用（出处命中@1 由 100% 降至 92.3%，
    根因是拒答阈值未按 cross-encoder 标尺校准），修复后恢复 98%
评测方法论：Wilson 95% 置信区间替代点估计（标注 n=16 下 ±25% 边界）
```

**面试要点**：RAG 面试重点是"你怎么知道检索变好了"——评测方法论（黄金集、置信区间）比实现细节更能打动面试官。

## Q9 登录认证重构（绞杀者模式）怎么保证零中断迁移？

**答**：
```
行为等价：baseline 五元组对拍（入参/前置数据/调用/输出/字节级响应）
          43 用例覆盖 22 接口，新旧系统双跑 diff 通过才算等价
迁移：v1/v2 共存灰度切流，适配器复刻 v1 有状态会话格式
      标注"绞杀债"待 v1 下线整包删除
抓出漏洞：施工中发现短信码校验整体缺失（任意码放行）→ 修复 P0 鉴权漏洞
```

**面试亮点**：重构项目要强调"零中断 + 行为等价可验证 + 过程中抓到隐藏 bug"——这是重构质量的最佳证明。

## Q10 你们怎么保证大重构不破坏行为？（特征测试/对拍）

**答**：三件套：
```
① 特征测试快照：改造前跑出结果基线，改造后 diff 对比（SQL 治理用，5518 行）
② 黄金 JSON 对拍：新旧实现跑同输入，输出逐位对比（导检算法，152 决策全等）
③ baseline 五元组对拍：入参/前置数据/调用/输出/字节级响应（认证重构，43 用例）
```
**共性**：都是"先锁行为，再改代码"——机器验证等价，不靠人工 review。
