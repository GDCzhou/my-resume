# QA：营销活动质量管理系统（保险展业管理平台）

> 来源项目：营销活动质量管理系统（保险展业过程管理与绩效考核平台）
> 简历对应：`opencode_write_resume.md` → "营销活动质量管理系统"
> 技术栈：Java · Spring Boot 2.6 · MyBatis-Plus · MySQL 8 · Redis · MinIO · EasyExcel · 企业微信开放平台 · React 19 · uni-app
> 代码位置：`~/work/yunpingtai/marketing/health-management-product-master`

## Q1 ⭐ 一句话介绍这个项目？

**答**：面向保险营销团队的一站式展业管理平台，服务 300+ 业务人员、沉淀 1.6 万+ 业务数据。核心是**展业过程管理**：管理员配置任务 → 业务员在企微 H5 提交面见/采集/增员记录 → **风控引擎实时打标**（防刷单）→ **每晚自动算绩效工资**。本质是**合规管控 + 绩效考核**。

**面试要点**：先说清"卖保险的业务员要报过程数据，平台要防他们造假"——风控存在的意义就是防刷单。

## Q2 ⭐ 为什么用单体多模块，不用微服务？

**答**：300+ 用户规模**单体完全够用**，微服务只会增加运维成本。用 Maven 多模块划分边界：

```
health-management-core           ← 公共层（统一返回体/全局异常/分页/工具）
health-management-server         ← 业务层（展业记录/任务/风控/统计，端口8023）
health-management-external-system ← 系统对接层（账号/组织/文件/企微/短信，端口8024）
health-management-client         ← 客户端/接口层
```

**面试要点**：主动说"模块化单体而非微服务"是**加分项**——说明你有规模判断力，不是无脑上微服务。

## Q3 两个前端怎么共用一套后端？

**答**：
```
管理后台（React）→ /healthApi/*（8023 业务接口）
企微移动端（uni-app）→ /healthApi/* + /systemApi/*（8024 系统接口）
统一 JWT + Redis 会话认证
```
业务接口和系统接口按端口拆分，前端按前缀访问，共用同一套账号和认证体系。

## Q4 ⭐ 风控规则引擎的数据模型？

**答**（`TbRule` 实体）：
```
主表 TbRule：name / rule（规则名）/ type（面见/采集/增员）/
             cycle（周期：小时/日/周/月）/ num（阈值）/ hours（小时数）/
             staffLevel（适用岗位）/ ruleType / num2（第二阈值）
命中表 TbRuleModel：ruleId + modelId（哪条记录命中了哪条规则，可追溯）
```

**关键**：规则**存库**，不是写死在代码里——加规则改库不改代码。

## Q5 ⭐ 风控是同步还是异步？命中逻辑怎么走？

**答**：**写入时同步判断**（`TbViewServiceImpl.saveTbView` L91-148）：

```
① 查启用的"面见"类型规则（L99-100）
② 按周期窗口 count 用户近期有效记录（L108）
③ 逐条规则比对：TbRuleModelUtil.getString(rule, count, ...)
④ 命中高风险 → setState("作废")（L131-138）
⑤ 保存命中记录 TbRuleModel（L148）
```

**性能**：就是几次 count 查询，开销极小。**同步**是因为要立刻拦截——刷单记录不能等异步才作废。

## Q6 周期窗口怎么算？

**答**（`TbRuleModelUtil` + `getBeginTimeForCycle` L152-159）：
```
日  → 当天 0 点
周  → 本周一 0 点
月  → 当月 1 号
小时 → 当前时间 - N 小时
统计条件：updated_time >= 窗口起点，count 该窗口内有效记录数
```

## Q7 多规则同时命中怎么定风险等级？

**答**：优先级 **高风险 > 中风险 > 一般**，`shouldUpdateLabel` 控制覆盖——命中高风险的记录最终标高风险，保证最高风险生效。订单/记录的 `label` + `labelContent` 落库，前端可见被哪条规则拦的。

## Q8 ⭐ 加一条新规则要改代码吗？

**答**：**不用**——规则存库 + 统一执行器遍历比对。但**新增"维度"**（新的考核统计口径）需要改代码，因为统计逻辑是写死的。**如实说边界**：规则可配置化，维度不可配置化。

## Q9 问卷/采集记录也跑风控吗？

**答**：**跑**。问卷项 `TbQuestionnaireItem` 也有 `label/labelContent` 字段（风控标签），`TbQuestionnaireItemServiceImpl` 里同样执行风控规则引擎——客户提交答卷时命中高风险同样作废。**所以风控覆盖面见/采集/增员三个业务入口**。

## Q10 ⭐ 绩效考核怎么算？（8+9 维）

**答**：
```
个人行为绩效 8 项，满分 100：
  业绩 35（≥5万/3万/1万/6千/3千 分档） + 面访 30 + 采集 15（<12次为0）
  + 增员 10 + 大拜访 20 + 报备 15 + 邀约 10 + 早会（预留，未实现）
管理考核 9 项：团队指标
工资 = 分数/100 × 岗位标准；低于最低合格分 → 工资为 0
```

**面试要点**：承认"管理考核的合计/工资、早会加分尚未实现"——坦诚边界比吹牛加分。

## Q11 ⭐ 定时任务怎么保证数据正确？（幂等重算）

**答**（`MyScheduledTask` 每晚 23:00 + `TbStatisticsItemServiceImpl`）：

```
@Scheduled(cron = "0 0 23 * * ?") → runAt23PM()
  → day_week() / month() / monthKh() / monthManageKh()

month() 幂等逻辑（L119-120）：
  先 delete(cycle = 当月)  → 清旧数据
  再 saveBatch(新统计)      → 批量插入
```
**先删后插** → 重跑不会产生重复数据，**幂等可重算**；`@Transactional` 保证失败不脏数据。

## Q12 业绩数据不在自己库，怎么拿？

**答**：**跨系统按用户名查"云 OA"**（自定义 SQL 查业绩/大拜访/报备），聚合进考核分。**强依赖外部数据源**——对方数据不规范会影响结果（如实说明）。

## Q13 ⭐ JWT 为什么要存 Redis？

**答**：纯 JWT 无法主动失效。Redis 存 token（`key = 前缀 + userId`，7 天）实现：
```
登出/踢人：删除 Redis 里的 token
请求校验：解析 JWT → 比对 Redis 中是否一致
```
**面试要点**：JWT 无状态是优点也是缺点（无法吊销）——"无状态 + Redis 可吊销"是折中方案。

## Q14 登录参数/密码怎么加密？

**答**：
```
传输：payload AES-128-ECB 解密（AesUtil.aesDecrypt，密钥=配置 salt）L119
存储：密码 MD5(固定盐 + 明文) 加盐
```
**面试要点**：主动说明 AES 密钥在前端只防传输偷看，**真正安全靠 HTTPS**；MD5 加盐也不如 BCrypt——可以提改进方向。

## Q15 拦截器怎么拿当前用户？

**答**：`LoginInterceptor` 解析 Authorization → 校验 Redis token → 用户信息放 `ThreadLocal` → Controller/Service 直接取；`finally` 中 `remove()` 防线程复用串线。这是 ThreadLocal 的标准用法，**一定要提 finally 清理**（防线程池串号）。

## Q16 ⭐ 企微登录和账号密码登录怎么统一？

**答**（`TbUserServiceImpl`）：
```
账号登录：login(payload) → AES 解密 → 校验 → 发 JWT（L109-161）
企微免登：authentication(code) → 企微 userinfo 接口换用户（L213-233）→ 同一套 loginSuccessTask
```
两条路最终都走 `loginSuccessTask`（L171）——发 JWT + 存 Redis，**会话体系完全统一**。企微 access_token 缓存 Redis（7 秒刷新窗口），微信 access_token 也走缓存。

## Q17 逻辑删除怎么做？

**答**：MyBatis-Plus 全局配置 `logic-delete-value`，删除自动转 UPDATE。可追溯，但查询要带过滤、历史数据会膨胀（如实说缺点）。

## Q18 文件存储怎么可切换？

**答**：`StoreEngine` 接口 + 本地/MinIO/OSS 三实现，配置切换——**策略模式**实际应用。微信 mediaId 拉流落库。

## Q19 分页怎么做？

**答**：MyBatis-Plus `IPage` + 自定义 XML 复杂查询 SQL，配合简单列表分页。EasyExcel 导出 1.6 万条级无压力。

## Q20 项目可改进的点？（主动暴露短板）

**答**：
```
① 风控同步 count → 可改异步 + 缓存计数（扛更大并发）
② 统计 1200 行硬编码 → 可收敛为配置化或 Drools 规则引擎
③ 管理考核合计/工资未实现 → 迭代中
④ 明文凭据 → 迁密钥管理
⑤ 前后端 API 类型 → OpenAPI 生成
```

**面试要点**：主动说短板 + 给方案是加分项——说明你有自省能力，不是只会报喜。
