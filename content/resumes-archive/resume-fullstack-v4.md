### 体检中心智能导检系统（0 → 1 主导）

**项目简介**：面向体检中心到院现场的智能导检与排队叫号系统，替代人工喊号与纸质指引，自动规划每位体检者的检查路径与叫号时机。覆盖体检人 H5、医生叫号端、商显叫号屏、楼层大屏、管理后台五端；按真实分院场地建模（3 层楼 / 12 个检查节点），单分院日均千级人次。

**技术栈**：Java · Spring Boot · DDD 六边形架构 · Redis · MySQL · MQTT（EMQX）· Vue 3 · Android WebView · ArchUnit · Docker/K8s

**核心职责与成果**：

- **架构设计**：主导 DDD 六边形分层，领域层零框架依赖，Redis / MQTT / HTTP 经端口下沉适配层；所有状态变更在单线程事件循环串行执行，从根上消除排队与号位竞态；ArchUnit 固化 11 条分层红线，全量单测 373 条、算法核心 61 项用例与 Python 仿真逐位对拍。
- **调度引擎**：将体检套餐建模为带前置依赖的任务 DAG，用「预计完工时间」替代「按队伍长度」选房间，解决彩超排长队、心电图空转的资源错配；自建策略对照仿真（300 人/组 × 10 组随机种子），相比纯挑短队基线平均等待降低 4.6%、在院时长缩短 4.4%，9/10 组占优。
- **瓶颈资源调度**：彩超 / CT / MRI 退出常规队列，改为资源组虚拟预约队列 + 水位自动叫号，前置未清者跳过而不失位，瓶颈设备利用率提升约 15%，高峰期门口排队人数减少 60%。
- **异常自愈**：30 秒巡查识别「末项超时 / 做完忘点 / 医生离岗」三类异常，自动软淡化、漏点回收、失败率熔断（超 0.6 跳闸、16 分钟冷却半开），过号休眠保位、熔断自动重导备用房间，现场无需人工盯屏。
- **多端推送**：MQTT（EMQX）推送叫号帧（retained + QoS1，断线重连不丢最后一帧）；设备零账号接入，bootstrap 下发 2 小时 HMAC 短期密码，长期密钥只走 HTTPS，上线至今零推送事故。
- **老系统替换**：老导检系统 20 个控制器 / 163 个接口原样兼容为契约层，接口治理后置以控制变更爆炸半径，分 4 个阶段灰度切换，任一步可回滚。

### 体检报告智能解读系统（RAG）

**项目简介**：面向体检中心报告解读场景的 RAG 智能解读系统，由 Python 检索增强服务与 Java Spring AI 生成服务构成，实现从知识库检索到报告解读的端到端链路，支撑综合解读、多学科解读与历年纵向对比，已部署到 3 家分院日常使用。

**技术栈**：Python（FastAPI）· Qdrant · Java · Spring Boot · Spring AI

**核心职责与成果**：

- **检索质量优化**：设计「宽召回（top-20）+ cross-encoder 精排」两段式检索，黄金集 A/B 实测 context precision 由 0.323 提升到 0.369（+14%）；定位重排副作用——出处命中@1 由 100% 降到 92.3%，根因是拒答阈值未按 cross-encoder 校准，修复后恢复至 98%。
- **评测体系建设**：用 Wilson 95% 置信区间替代点估计，标注 n=16 下 ±25% 误差边界；用语言切片量化跨语言偏置（中文 top1 0.689 / 英文 0.546），为中英文知识库分开调参提供数据支撑。
- **医学可信治理**：临床规则图谱 + 证据溯源 + 拒答机制，资料不足明确拒答，幻觉率从初期的约 18% 降至 5% 以内；知识库全本地可内网部署，外部模型调用前实施数据脱敏。
- **多模型调度**：统一接入 4 个模型并按优先级自动降级，按次核算 token 用量与成本，相比单一 GPT-4 方案成本降低约 40%。

### 智慧健康云平台

**项目简介**：连锁体检中心的一体化健康管理平台，基于 Spring Cloud Alibaba 微服务架构，拆分 18 个服务模块、20 个业务库（交易核心库 272 张表约 10GB，最大单表 915 万行）；核心链路覆盖个检、团检、实物、储值卡多类订单与组合支付，对接 OA、短信等外部系统。

**技术栈**：Java · Spring Boot · Spring Cloud Alibaba · Nacos · MySQL · Redis · RocketMQ · Seata · Docker/K8s

**核心职责与成果**：

- **团大单异步化改造**：企业团检千人级订单原同步链路耗时 20+ 秒且偶发超时，引入 RocketMQ 将合同审批、订单及服务单创建拆为异步链路，批量写入 + 分段事务 + 延时消息实现削峰，接口响应降至 500ms 以内，峰值并发支撑提升 5 倍。
- **秒杀与营销活动**：负责秒杀、拼团、砍价活动下单与超时失效，设计 Redis 预减库存 + Lua 原子扣减防超卖 + MQ 异步下单方案，活动期间 5000+ 并发零超卖，库存数据与最终对账完全一致。
- **支付与对账体系**：设计储值卡、微信、现金组合支付方案，金额按项目分摊并处理尾差；订单、支付、退款与营收自动对账，异常自动发现告警，上线至今账实差错率为 0。
- **订单一致性保障**：支付以回调为准，超时未支付自动关单 + 自动退款兜底，订单与支付状态通过状态机约束，资损风险降至接近零。

### 登录认证服务 DDD 重构

**项目简介**：旧认证服务由 560 行上帝类 SysLoginService 扛下 9 种登录方式，一个方法混入校验、调远端、写 Redis、审计、签 token 五件事，且缺少失败锁号等防暴力破解机制（P0 安全漏洞）；主导 DDD 分层重构，零中断迁移。

**技术栈**：Java · Spring Boot · Spring Cloud Alibaba · Redis · JWT · ArchUnit

**核心职责与成果**：

- 将上帝类拆分为分层架构 + 9 个登录适配器，新增登录方式从改几百行核心代码变为加一个适配器，迁移期间线上零故障。
- 失败 5 次锁号 30 分钟、3 次强制验证码等规则收进聚合根 LoginAttempt，改锁号时长只改一个常量、规则可单测，覆盖率 100%。
- 端口倒置，业务层定义接口，Redis / Feign / 签 token 全部下沉适配层，换 Redis 只换一个实现类、业务零感知。
- 重构中补齐失败锁号、密码明文传输等 P0 安全漏洞；分层红线固化进 CI（ArchUnit），防止架构回退。
