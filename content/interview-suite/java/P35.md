# P35 怎么用 Java 实现一个简单的消息队列

**面试题**：不借助 MQ 中间件，用 Java 怎么实现一个简单的消息队列？核心组件有哪些？

## 核心组件

一个消息队列最少需要四部分：

1. **消息存储**：存放待消费的消息（队列）；
2. **生产者**：往队列写入消息；
3. **消费者**：从队列取出消息处理；
4. **协调/解耦**：生产消费速率不一致时的缓冲、ack 确认。

## 简单实现思路

### 版本 1：BlockingQueue（最基本）

```java
BlockingQueue<Message> queue = new LinkedBlockingQueue<>(10000);

// 生产者
queue.put(new Message("hello"));

// 消费者（独立线程）
while (true) {
    Message msg = queue.take();  // 队列空则阻塞
    handle(msg);
}
```

用 `put/take` 天然实现"队列满阻塞生产者、队列空阻塞消费者"，就是最简单的 MQ。

### 版本 2：多生产者多消费者 + 线程池

- 生产者线程池写队列；
- 消费者线程池 `take` 消费；
- 用 `CountDownLatch/AtomicInteger` 统计积压，做背压（积压过多暂停生产）。

### 版本 3：进阶设计（贴近真 MQ）

```text
队列存储：数组/链表，支持 FIFO，可选持久化（写文件/DB）
ACK 机制：消费成功才移除；失败重试（放到重试队列）
消息模型：topic 路由（Map<topic, Queue>）
多消费者：同一队列多个消费者抢消息
```

## 面试官真正想考察的

1. **数据结构选型**：为什么用阻塞队列（生产消费解耦、缓冲）？
2. **并发安全**：多线程读写队列如何保证安全（锁/ConcurrentLinkedQueue/阻塞队列）？
3. **可靠性与 ack**：消息处理失败怎么办？丢消息怎么防？
4. **与真 MQ 的差距**：缺持久化、高可用、顺序保证、消息回溯、集群横向扩展。

## 加分点

- 说出生产消费模型 + 缓冲的作用（削峰填谷）；
- 提到**幂等消费**：消费端处理要支持重复投递；
- 提到底层本质：MQ ≈ **数据结构（队列）+ 并发控制 + 存储 + 协议**，理解了就能自己实现简易版；
- 追问"怎么保证不丢消息"：持久化落盘 + 确认机制（生产端 ack、消费端 ack）。

## 一句话总结

用 `BlockingQueue`（LinkedBlockingQueue）做队列，生产者 put、消费者 take 即可实现一个线程安全的简易 MQ；再叠加 topic 路由、线程池、ACK/重试、持久化，就越来越接近真实消息队列。
