# P81 Dubbo 中的异步调用是如何实现的？它有什么优势和注意事项？

**面试题**：Dubbo 的异步调用怎么实现？优势和坑？

## 1. 什么是 Dubbo 异步调用

默认 Dubbo 是**同步阻塞**：调用方线程发出请求后等待响应。

异步调用：调用方**不阻塞等待**，发完请求继续做自己的事，响应到了再回调/取结果。

## 2. 实现方式

### ① CompletableFuture（推荐，2.7+）

```java
// 接口返回 CompletableFuture
public interface GreetService {
    CompletableFuture<String> sayHello(String name);
}
```

```java
CompletableFuture<String> future = greetService.sayHello("jack");
// 不阻塞，注册回调
future.thenAccept(result -> log.info("结果：{}", result));
```

### ② RpcContext（旧方式）

```java
RpcContext.getContext().asyncCall(() -> greetService.sayHello("jack"));
// 之后通过 RpcContext.getContext().getFuture() 拿结果
```

### ③ 配置层面

```xml
<dubbo:reference id="greetService" interface="..." async="true"/>
```

## 3. 优势

- **提升吞吐**：调用方线程不用干等 IO，可以并发发起多个远程调用（比如并行调 3 个服务再聚合）；
- **降低线程占用**：高并发场景避免线程池被打满；
- 响应式编程：链路可以串成回调流水线。

## 4. 注意事项/坑

- **上下文传递**：异步回调里的 RpcContext 不再可靠（上下文随发起线程），需要显式传递；
- **异常处理**：future 要处理 exceptionally，否则异常静默丢失；
- **超时与取消**：异步也要配置超时，避免无限等待；
- **线程安全**：共享 future 多线程读写要小心；
- 别把同步调用包在异步里（伪异步），要真正用非阻塞模型；
- 消费端线程池与 IO 线程模型要理解清楚（Dubbo 有业务线程池和 IO 线程）。

## 5. 加分点

- 能说出 Dubbo 异步底层：请求发出后返回 Future，响应由 IO 线程写回，触发回调；
- 与"CompletableFuture.allOf 聚合多个 RPC"结合讲，体现实战；
- 提到与响应式/虚拟线程的关系：JDK21 虚拟线程也能改善同步阻塞模型的成本。

## 一句话总结

Dubbo 异步通过接口返回 `CompletableFuture`（或 RpcContext.asyncCall）实现，发完请求不阻塞、回调取结果，能显著提升并发吞吐；注意回调里的上下文、异常、超时处理和"别伪异步"。
