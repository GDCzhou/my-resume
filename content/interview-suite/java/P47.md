# P47 面试重灾区：逃逸分析与栈上分配 - java 对象一定是在堆上分配的吗？

**面试题**：Java 对象一定在堆上分配吗？什么是逃逸分析？什么是栈上分配？

## 1. 答案

**不一定。** JIT（如 C2）通过**逃逸分析**判断对象不会逃逸出方法时，会把它**分配在栈上**（甚至**标量替换**，连对象都不建），只有逃逸的对象才在堆上分配。

## 2. 什么是逃逸分析

分析对象的**作用域**：

- **不逃逸（No Escape）**：对象只在当前方法内使用，没有被其他线程/方法引用；
- **方法逃逸**：作为参数传给其他方法 / 被返回；
- **线程逃逸**：被赋值给其他线程可访问的变量（最严重）。

```java
public void test() {
    Point p = new Point(1, 2);  // p 只在方法内使用，不逃逸
    System.out.println(p.x + p.y);
}
```

## 3. 逃逸分析的三个优化

### ① 栈上分配（Stack Allocation）

不逃逸的对象直接在**栈帧**上分配，方法结束随栈帧弹出而销毁，**无需 GC 参与**，减少 GC 压力。

### ② 标量替换（Scalar Replacement）

对象拆成多个基本字段（标量），直接在局部变量/寄存器中使用，**连对象都不创建**：

```java
Point p = new Point(1, 2);
// 优化为：int p_x = 1; int p_y = 2;
```

### ③ 锁消除（Lock Elimination）

不逃逸对象上的同步块，锁无意义，直接消除。

## 4. 为什么"对象都在堆上"是错的

- 传统教材讲"对象在堆上"，那是**语言规范视角/未优化时**；
- 开启逃逸分析（JDK 默认 `-XX:+DoEscapeAnalysis`）后，热点方法里的小对象常被栈上分配/标量替换；
- 用 `-XX:+PrintEliminateAllocations` 可以看到标量替换效果。

## 5. 加分点

- 举例：for 循环里 `new` 的小对象（如包装类型、简单 DTO），满足条件会被标量替换，所以"循环里 new 对象性能差"在 JIT 下不一定成立；
- 注意：**大对象**不适合栈上分配；逃逸分析有成本，JIT 只对热点方法做；
- 关联问题：TLAB（线程本地分配缓冲）是堆内优化，别和栈上分配混了；
- 面试官若追问"如何验证"：`-XX:+PrintEscapeAnalysis`、`-XX:+EliminateAllocations` 等 JVM 参数。

## 一句话总结

JIT 逃逸分析发现对象不逃逸出方法时，可做**栈上分配、标量替换、锁消除**，所以 Java 对象并不一定在堆上；逃逸对象才进堆，这决定了 GC 压力和分配性能。
